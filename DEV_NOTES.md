# Admin build conventions (revamp to the client's role sheet)

Stack: React 18, Vite, TypeScript strict, Tailwind 3, react-router 6 (data router), zustand 5, react-hook-form + zod 4 (`@hookform/resolvers/zod`), recharts 3, date-fns 4, cmdk, @dnd-kit, lucide-react. Aliases: `@/app @/layout @/pages @/components @/permissions @/navigation @/shared @/mock @/lib @/styles`.

## What the revamp changed (already done by the lead — do not redo)
- **Roles** (ids unchanged, labels per the client): `super_admin` "Super Admin", `editor` "Editor", `associate_editor` "Associate Editor", `reviewer` "Reviewer", `panel_member` "Review Panel Member", `support` "Support Executive". Never write "Journal Editor" or "Support Staff".
- **Sidebar = explicit per-role menu** in `src/navigation/nav.ts` (`ROLE_MENUS`, client's exact module names). Pages never decide the menu. `PageHeader` automatically replaces its `title` with the client's module name when the page is a role's menu entry, builds the breadcrumb and shows "To confirm / Under discussion" badges from the nav config; pass `badges={['Proposed']}` for flag-gated items.
- **Section tabs**: `SECTIONS` in nav.ts render a tab strip above the page (e.g. Editor: Manuscripts · Review management · Payment verification · Final approval). They are rendered by `AppLayout`; do not add your own tab strip for those.
- **Permission matrix** `src/permissions/matrix.ts` was rebuilt from the client sheet. Areas: dashboard, submissions, reviewMgmt, myReviews, reviewAssign, production, finalApproval, backdated, postPub, issues, conferences, doi, certificates, payments, invoices, referrals, dispatch, commLog, templates, notifications, whatsapp, inbox, helpdesk, chatbot, cms, blog, board, announcements, awards, awardApproval, forms, journalMetrics, newsletter, analytics, scholar, users, journalSettings, audit. Levels: none < view < work < approve < manage. Read levels with `usePermission(area)` / `useCan` / `useCanAct(area, min, assignedIds)`; disable lacking actions with `GuardedButton` + `why()`. Never hard-code role names in pages.
- **Feature flags** `src/permissions/flags.ts` (read with `useSession((s) => s.flags.x)` or `useSession.getState().flags`): reviewPanel, correctionFee, newsletterCampaigns, emailInbox, websiteChat, seoAutoLink (all ON by default) and reviewerSeesAll (OFF). `FLAG_META[flag]` gives label/description/badge ("Proposed", "Under discussion", "To confirm"). Flag-gated UI shows a small `<Badge>` with that badge text.
- Every module route must be registered in your area's `src/pages/<area>/routes.tsx` (`PageDef[]`: `{path, area, min?, element}`). Paths that exist in nav.ts but have no registered page show a placeholder, so registering your path replaces it. New paths: `/journal-metrics`, `/notifications`, `/newsletter`, `/blog`, `/inbox`, `/review-assignments` (plus existing ones).

## Rules for every screen
1. Data goes through async API modules in `src/mock/api/<name>.ts` (`delay()`, same function names a real API would use), read/mutate zustand stores, respect the journal scope (`useScoped`). Mutations toast, persist for the session and call `recordAudit` (+ `logEvent` for paper changes). New seed data lives in `src/mock/data/<name>.ts`, stores in `src/mock/stores/<name>.ts` with `registerReset`.
2. Every decision/rejection/retraction/Return to Production/verification rejection needs a reason (`ReasonDialog`). Irreversible/public actions use `ConfirmDialog` with consequences.
3. Show only actions allowed for the status and level; otherwise disabled with a tooltip. "Work on" = only items assigned to the user.
4. Quality: inline validation (react-hook-form + zod), skeleton loading, empty states with a next action, error state with retry, toasts, unsaved-changes warning on long editors, keyboard accessible, labelled inputs, responsive (DataTable stacks to cards on mobile), WCAG AA. Paper IDs never truncate; long titles wrap to 2 lines (`line-clamp-2`) with full title in `title`. Dates `formatDate`, money `formatMoney`, relative times with `RelativeTime`. Realistic content only — no lorem ipsum, no placeholder screens.
5. Visual: neutral slate + indigo accent via existing classes (`card`, `btn-primary/secondary/ghost/danger`, `input`, `label`, `kbd`). No journal brand colours except the journal dot/badge. Charts: recharts + `@/styles/tokens` `CHART_COLORS`, `role="img"` + aria-label + text alternative; load the `dataviz` skill before chart code.
6. Out of scope: author/reader login, AI features, plagiarism checks, real payment/messaging integrations. Never touch `D:\Automated Journel\frontend`.
